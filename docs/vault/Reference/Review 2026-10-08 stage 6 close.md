## The four holes, and what happened to each

### 1 — the contrast gate could not go red (FIXED, mutation-proof)

`scripts/a11y-contrast.mjs` computed WCAG ratios from a HAND-KEYED hex table: the numbers were
right, but the table never read `src/ui/shell.css`, so regressing any color in the stylesheet left
the gate green — the README/audit claim "fails CI-red on any regression" overstated the truth.
Rewritten: every color is now RESOLVED AT RUN TIME from the real `src/ui/shell.css` (plus the one
inline cssText in `src/boot.ts` that styles the sound toggle), background stacks are composited from
the actual `background` declarations, the dim factors are READ from the CSS `opacity` declarations,
a selector whose referenced declaration vanished is a DRIFT failure, and a style split across
selectors in one row must stay equal or the run is red. The table output stands (one merged row
split: the tray reason line now audits on its own).
Mutation-proved on this branch, each mutation reverted after observation: a replay tick darkened to
#d8c49a → 1.17 FAIL, exit 1; the body ink lightened to #b9a488 → 3 FAIL, exit 1; deleting the
fingerprint ink declaration → DRIFT, exit 1; clean tree → exit 0 with the same ratios the audit
note prints (12.22 / 5.39 / 15.03 / 8.49 / 14.49 / 3.92). The claim in
`Reference/Accessibility audit 2026-10-08` is now true as written.

### 2 — an unnamed guard printed "blocked — the  is in the way" (FIXED, mutation-proof)

`blockerOf` in `src/ui/builder.ts` guarded only `name === ''`. A set object hanging under an ANONYMOUS
first path segment (the walker joins the object PATH, so an unnamed group under `dress` paths
`/mug-body`) gave `solidWord` an empty top segment, and `ghostCopy` interpolated the hole straight
into the sentence. Fixed with `guardWord`: `solidWord` of the path, falling back to the VERB TABLE's
own furniture word when no top segment is sayable — which `ghostCopy` renders as exactly the shipped
`GHOST_LABEL.blocked` line, "blocked — furniture is in the way": the blocked-rung copy law, never a
blank. Pinned by `tests/unit/set-wiring.test.ts` (empty name, leading-slash name, and the named case
byte-checked); delete the fallback and the spec is red. No shipped guard hits the fallback —
`tests/unit/named-props.test.ts` keeps every set path fully named — this is the copy law made
unbreakable for the next set author.

### 4 — the replay:all claim, stated honestly (DOCUMENTED — pin assert NOT added)

`replay:all`'s teeth ARE what the reviewer's ledger says: per rung, both runs finish, the two hashes
are EQUAL, the measured time respects `parTime`, and the tray count equals parPieces — pair-equality
plus par respect, NOT a per-level hash pin. The pin question: `src/world/pars.json` carries only
levelId / parPieces / parTime — NO per-level hashes — so there is no pin field for `tools/replay-all.mjs`
to assert against, and one was deliberately NOT added. Why not: `pars.json` is REGENERATED by
`npm run pars` (brief §9.2), so a hash stored there is re-stamped silently by the same command at
every geometry change — a pin that re-pins itself is not a pin. The honest anchor lives where a
human re-pins with a reason: the `PINNED` table in `tests/unit/set-wiring.test.ts`, whose comments
ARE the re-pin history (the stage-3 wiring seam, the L02 discoverability pass, the K3 re-sweep), and
which `replayRun` re-derives at that seam. The README states replay:all's claim as pair-equality +
par respect, which is exactly what the gate proves; the hash-anchor claims live with their own
evidence and are unchanged. If a future seam ever wants an all-30 pin, the right shape is a pinned
fixture checked by a UNIT spec with a comment trail — not a field `npm run pars` rewrites.
