# Accessibility audit 2026-10-08 (stage 6)

> [!abstract] Role
> The honest stage-6 audit against the brief: contrast, focus visibility and tab order, screen-reader labels, colorblind safety, reduced-motion coverage, keyboard end-to-end, and the touch pass at 390 px and 820 px. Every row states WHAT WAS MEASURED and WHERE IT IS PROVEN now. Fixed rows are fixed in this branch; accepted rows carry their reason. Evidence: `node scripts/a11y-contrast.mjs` (the contrast table below, computed from the CSS colors), `tests/e2e/a11y.spec.ts` + `tests/e2e/a11y-touch.spec.ts` (the gates), and the tab-stop screenshots under docs/explorations/a11y/ .

## Findings

| # | surface | finding | severity | status | evidence / reason |
|---|---|---|---|---|---|
| 1 | whole page | **Tab was the tie-walk under world focus** — with focus on the body (the page's default state) the first Tab pressed preventDefault and cycled aim instead of moving focus, so a keyboard user could NEVER reach a button by Tab. The worst finding of the audit; every prior "keyboard" proof had used focus() or the arrows, which is exactly why it survived five stages. | serious | **FIXED** | Tab is removed from the builder keydown table entirely — Tab is the browser's focus walk on every element, `[ ]` walk ties (the hint only ever advertised `]`). `tests/e2e/a11y.spec.ts` walks the real Tab chain and asserts every control is a stop exactly once with no repeats; `tests/e2e/aim-depth.spec.ts` now walks the tie with `]`. | 2 | launch | **No key ever launched a run** — the only keyboard launch was parking focus on the Launch button (and every button blurs after activation by the P+Q policy, so "focus the button, press Enter" is a two-step dance the page never taught). | serious | **FIXED** | `l` launches from world focus (body / canvas / the builder group) through the SAME startRun as the button; over a focused control `l` is just a letter. | 10 | touch | **There were no touch verbs at all** — orbit is right-drag (a finger has no second button), a touch had no hover so a tap aimed at the STALE target (the ghost appeared only AFTER the place), and a two-finger release could count as fresh place intent. | serious | **FIXED** | `attachBuildView` now: aims AT TOUCH-DOWN (the ghost answers the landing finger before the lift decides), TWO-FINGER DRAG is the orbit stand-in for right-drag and never places, and the untracked-release fresh-intent rule is mouse-only (a lifted second finger places nothing). canvas gets `touch-action: pan-y pinch-zoom`: vertical drag scrolls the page, SPREAD stays the BROWSER's pinch zoom (a magnifier is an accessibility feature; its pointercancel ends the orbit with no verb), horizontal and two-finger drags reach the app. 44 px tap boxes under pointer:coarse. ## The keyboard end-to-end (brief's own test)

kitchen01, no pointer, no focus() shortcut: Tab to the tray button → its native Enter HOLDS (focus returns to the world by the P+Q policy) → the world's Enter PLACES (three times — the default target rides the chain head each time) → L LAUNCHES → the panel appears with the star → Tab to Retry/Next, Enter acts. That paragraph IS `tests/e2e/a11y.spec.ts` (test: "keyboard end-to-end"), plus the traversal test that pins the whole stop list. The hint line now teaches it: "…Flip: R · Launch: L · Look: right-drag · Home: press Esc twice" (`Modules/ui` keeps the copy pinned; two older specs carry it verbatim and were updated with the law).

## Reduced-motion sweep ledger (Feel.md's law: every animation has a no-motion equivalent)

| motion | still equivalent |
|---|---|

| help-drawer turntable (12 Hz spin) | one still frame at STILL_ANGLE — already honored, now via the shared source |
| replay cinematic blends + autoplay | REPLAY_BLEND 0 + PAUSED default under reduce (spec-proven) |
| juice (squeak/squash/dust/chime) | JuiceFeed reducedMotion collapses durations — system not yet wired into a live world (unit-proven); when it ships the flag rides the same source |
| build/run camera damping | GAMEPLAY framing, not decoration — kept under reduce (accepted: a still camera makes the run unreadable; there is no vestibular trigger — no shake ships, Feel.md's own law) |
| CSS transitions | none exist; the media block is the belt |

## Contrast table

Printed by `node scripts/a11y-contrast.mjs` (26 pairs incl. composites: the panel over paper AND over a bright canvas, the badge over its own alpha, the dimmed states marked EXEMPT-with-number, the two focus-ring layers). Every color is RESOLVED AT RUN TIME from `src/ui/shell.css` (plus the sound toggle's one inline cssText in `src/boot.ts`) — a color edited in the stylesheet moves these numbers, a vanished declaration goes red with DRIFT (stage-6 close: the table is no longer hand-keyed). All non-exempt pairs pass; the script exits non-zero on any regression.

## How to reproduce the audit

`node scripts/a11y-contrast.mjs` · `E2E_PORT=<4420+> npx playwright test a11y.spec.ts a11y-touch.spec.ts` · screenshots in docs/explorations/a11y/ (tab stops 1/3 on the game page incl. the world's own group stop, a locked level-select rung, the dark-panel Retry ring, phone/tablet build+result). Live-browser tab-order probes were driven on the production preview build before the fixes and are what rows 1–5 came from.
