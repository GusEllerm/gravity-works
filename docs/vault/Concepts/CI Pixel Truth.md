# Concepts/CI Pixel Truth — pixel truth must exist on CI's machine too

> [!abstract] Law
> A pixel assertion that can only fail on one person's laptop is not a gate. Every pixel view declared
> CI-enforced must have a committed baseline **for the platform CI runs on**, and a missing one is RED
> under `CI`, never the loud-but-green skip. This closes the class of the bloom-merge incident: a merge
> clobbered the darwin shell baseline (tests/visual/darwin, the shell-kitchen01-idle capture), the restore
> shipped, and CI stayed green for
> days because the only machine that could tell truth from clobber was one Mac
> (`Reference/Evaluation 2026-10-11 engineering round2.md` N1; Decision Log 2026-10-12 "pixel truth must
> exist on CI's machine too").

## The mechanism

- `CI_ENFORCED_VIEWS` in `tests/e2e/visual.spec.ts` names the views under the law. A view joins by
  surviving two tests of frame stability: consecutive captures identical within the 0.1 % gate, on the
  exact renderer the baseline will be judged by. First member: `shell-kitchen01-idle` — the shipped
  shell at `/?level=kitchen01&post=on`, settled idle (nothing animates on the table, liquid `uTime`
  stays 0), fixed 1600x900 viewport, canvas's own 960x540. Second member (downhill build 2, the
  front door): `shell-home-idle` — the BARE-route home screen addressed explicitly
  (`/?boot=house&post=on`), the parked crane's cross-section with no run and no ghost race begun —
  a static table by construction; its linux truth is bootstrapped by the same `linux-baselines`
  job line (extended per-view `test -f … || capture`). The canonical kitchen-set shots stay on the
  old doctrine; the exploration-vs-ratified cross-check (`againstExploration`) is unchanged.
- `againstBaseline` under `CI=1`: enforced view + missing baseline = hard failure; every other missing
  baseline keeps the loud skip (fresh clones on unlit platforms still run), and the darwin gate and its
  regeneration doctrine (`GQA_UPDATE_BASELINES=1` on the Mac) are untouched.
- Baselines for a new platform are generated BY a CI run, not on a laptop: the `linux-baselines` job in
  `.github/workflows/ci.yml` captures missing views on ubuntu/SwiftShader with rebase mode's
  double-capture frame-stability self-check and commits the PNGs to the PR branch. The PNGs land as a
  reviewable PR diff — the human-eyes condition the 2026-10-07 Decision Log demanded of generate-in-CI —
  and `check` needs that job and checks out the PR branch head, so the assert itself (red or green) runs
  in the same PR run. Once committed, the job is a no-op; on main pushes it is skipped.
- SwiftShader determinism is assumed nowhere: rebase mode gates TWO consecutive captures
  (`REBASE frame-stability self-check`), and the same-run `check` job re-compares in a fresh process
  against the committed PNG. That is the honest frame count for the capture path.

## What a pixel change does

A code change that moves an enforced view's pixels goes RED on CI regardless of the committer's machine;
deliberate art changes re-take via the bootstrap flow (delete the platform PNG(s) in the PR, CI re-captures
them onto the branch) or `GQA_UPDATE_BASELINES=1` on the platform in question. Prove the non-vacuity any
time: `CI=1 GQA_BASELINE_DIR=tests/visual/linux npx playwright test visual -g "game shell"` on a box with
no such file must FAIL, not skip.
