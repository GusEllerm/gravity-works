# Modules/ui

> [!abstract] Role
> The builder UI (brief §9.1): tray, socket snapping, ghost, budget counter. Plain accessible DOM so the stage-6 a11y pass extends rather than rebuilds it. Owner: Systems Engineer.

## What it does

`src/ui/builder.ts` — `createBuilder(host, { level, build, tray?, trayParams?, solids?, onChange })` renders `#gw-tray` (a real `<button>` per kit kind from `PIECE_KINDS`, `data-kind`, aria-pressed; tray kinds' labels are the DECREMPENTING legend "drop ×1" → "×0" — ×N counts what is LEFT to place, the line playtest G read as stuck; since playtest M every button word is the kind's PLAYER word from `PIECE_LABELS` — `gapLip` renders "Lip", `finishCup` "Cup", `springLauncher` "Spring" — with the codename surviving only as the element/`data-kind` id, and locked/spent messages say it in the same word), `#gw-piece-count` ("n of budget pieces used" — **n counts TRAY placements**, never built-in fixtures), `#gw-ghost-state` (EMPTY when nothing is held — the internal `GhostState` words never reach the screen; `GHOST_LABEL` maps them to the VERB TABLE copy), `#gw-target-label`, and the `#gw-place` / `#gw-rotate` / `#gw-remove-piece` / `#gw-reset` / `#gw-launch` buttons (`#gw-reset` is the permanent **Retry** — since playtest N ("Retry only appears in the result panel") the as-built retry lives OUTSIDE the panel: the button word is "Retry", the id stays `gw-reset` (a test surface, not copy), and the shell wires it and the panel's `#gw-result-retry` to the SAME `resetCar` — car home, build kept, panel away, so a dismissed panel never hides the way back). Tray gating (brief §9.3): with a `tray` map, kinds outside it are aria-disabled, a kind's placements are capped at its tray count, `playerCount()` is the budget/result tally, Remove never deletes a fixture and is ONE SPOKEN SHOT PER CLICK since playtest Z round7 (two clicks "eaten" with the counter unmoved read as a mode quietly turning itself off — there is no mode, and every shot now speaks on `#gw-ghost-state`: success `removed the <piece>`, refusal `nothing to remove — the track is empty` / `nothing to remove — only the level’s own pieces are on the track`; the Delete/Backspace keys are the same spoken path — no silent state drift; **and since program T2.1 the BUTTON NAMES WHAT IT TAKES** — its text is `Remove the <piece> <locator>`, the piece from `removeIndex`, the scan `removeLast` performs (ONE source: the label cannot drift from the click), the locator from `removePhrase` in the socket-graph words the ring and the note already speak — `by the ramp` (the anchor its entry is joined to), `past the cup` (seated on the goal's own exit — the orphan the MOVE clause names), `at the car’s start point` (the bare release socket), `you placed last` (the LIFO law itself, for a piece the graph can locate by nothing else), with the law stated outright in `title`/`aria-label` and the plain `Remove piece` standing when the button owns nothing — the spoken `removed the X` line is unchanged), and the held kind is PLACED with the level's tuned `trayParams` (derived in `src/ui/advice.ts` (`levelTrayParams`) from each kind's first `parBuild()` placement, or from the level's own `trayParams` declaration for a kind the par line never places — L02's arc-route `gapLip`/`landing`, and since the stage-4 fail-timing pass its locally-tuned `drop`/`straight` geometries reach the tray the same way (one geometry per kind is the contract `trayParityBuild` checks); kit DEFAULTS would build a different gap than the level was par'd on). The target line speaks the same words (playtest M retired "end of `finishCup`"; the R+S sweep retired the internal nouns too — the cup's open exit reads "target: cup on the table", an open release socket "target: the car's start point" (reworded at playtests Y+X round6 — "where the car starts" read as a PIECE name), an exit of a piece whose kind the tray never stocks reads "end of the pre-built X" — a target may name a visible built-in but must never name a greyed kind as if it were placeable (playtest Y item 4, the kitchen02 run-out "end of curve"; swept by `tests/e2e/playtest-y-clickdiff.spec.ts`), never "end of cup"/"level start" — and since playtest Z round7 the line's VERB disambiguates aim from goal: WHILE HOLDING a piece it reads "place drop at: X" (an aim, a spot to put it — "target" was doubling as the star rules' goal), empty-handed the ring keeps the neutral "target: X"), and the R/Flip press answers with a passive "· rotated" tail on `#gw-ghost-state` when the ghost is on screen (playtest M: "R-flip has no visible confirmation text"); with NOTHING held the press is no longer mute either — the FIRST press of a session that ARMS the reversal says what it did, `REVERSING_WHY` — "reversing — track runs backwards this way (press R unless you want a coaster)" (playtest R's K4 wall: one stray ghostless R silently armed the reversal of every later mount, seen only in the diagnosis; the FLIP_WHY discipline applied to the ARM instead of the FIT, once per page session, the next action — the first place included — retiring the line and the held ghost's own copy taking the line over). ONE geometry per kind is the tray's whole contract: a level that chains the same kind at two sizes has a par build no tray can place (`trayParityBuild`, `tests/unit/kitchen-levels.test.ts`). The gating reason is ON-SCREEN, not a hover title: `#gw-tray-reason` states "Greyed pieces are not in this level · ×N counts pieces left to place · pieces already on the track came with the level" (the third clause is playtest Z round7 — "a piece listed with no ×N, yet 4 of 4 used — which pieces did I actually own?": greyed = not stocked, ×N = stock counting down, built-in = the level's own, never in the tray and never counted), every aria-disabled button carries `aria-describedby="gw-tray-reason"`, and clicking a locked or spent button says which in `#gw-ghost-state` (playtest C: "state and appearance disagreed") — and since playtest N the spent/locked lines also name the piece IN HAND when it differs ("no Landing left in the tray — you are holding Lip"), because both M and N read a bare kind-named message as a verdict on the held piece; the companion fix is that hovering a SPENT tray button no longer steals the hold (`mouseenter` selects only a `selectable` kind — the silent hover-swap was the actual origin of the contradiction). THE GHOST AND THE RING BELONG TO THE BUILDER, NOT TO A WORLD (R7, program-T0.6 mirror of the set-group law): `setScene` moves them into each freshly built scene and the shell calls `liftFromScene()` BEFORE `world?.dispose()` on the old one — `World.dispose` disposes every mesh material it finds in the scene it frees, and these two are created ONCE, so left in place every placement paid a shader recompile and a geometry re-upload for the ghost and the target ring (a placement-time hitch on weak GPUs, no correctness loss). The set's own group is pulled out by the same `rebuild` for the same reason.
