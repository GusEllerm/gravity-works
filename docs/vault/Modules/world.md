# Modules/world

> [!abstract] Role
> `World` — the contract's spine object (see [[Concepts/Track Kit|Track Kit]]): one object owning physics, scene and the track graph for one run attempt, plus the `Level` shape every role builds against. Owner: Systems Engineer.

## What it does

- `src/world/world.ts` — `World`: `constructor(level, build, opts)` (via `World.create`, which awaits `initRapier` first) reifies the `Build` into ONE fixed body carrying every `spline.toColliderDescs(RAPIER, { scale: SIM_SCALE })` hull (group `TRACK_GROUP` = `0x0001_fffd` — bit0 member, filter EXCLUDING the chassis bit1, matching `src/feel/kittrack.ts`; never the default all-ones group, see [[physics]] gotchas), builds plain-material meshes when `visuals` is on, and spawns the raycast-wheel car from `src/physics/car.ts` at the level's `startSocket`, advanced `SPAWN_ADVANCE` (2 cm) down the tangent (a car centred ON the socket hangs half its wheelbase over the deck edge and slides off backwards — measured, do not re-tune blindly). Track colliders are built with `TRACK_FRICTION` IMPORTED from `src/track/material.ts` — the same rubber every feel rig measures with (it used to be a local 0.6 with a comment claiming it matched the rigs; stage-2 review MAJOR).
  - The chassis-excluding filter is load-bearing here too (measured 2026-10-05 with the real feel track in `World`): with the old filter-all `0x0001_ffff` the chassis collider hoovered the loop's ~3 mm chord risers — a 5 m/s² energy-pumped ramp descent and an anchor at the loop bottom, never terminating. Support rays are unaffected (they're cast without a group filter, and the wheel-exclusion predicate reads MEMBERSHIP, not the filter mask), the deck stays visible to suspension; the `wheelColliders` bake-off variant still physically touches the track (bit2 stays filtered-in).
- `step()` is the contract's fixed 1/120 s in the fixed order **inputs → car forces → physics → constraints**: launcher triggers (world `power` enters the sim as a sim-space Δv via `power * SIM_SCALE`) → `carStep` (with the level's hazard `gripAt` field when it has zones — see [[hazards]]; `HazardField.fromLevel` runs once in the constructor, and a zone-free level passes no callback at all) + `applyRollingResistance` (given the step's `support` so per-wheel grip shares apply) → `stepWorld` → state hash every `HASH_INTERVAL` + `observe` (cup capture at `CUP_CAPTURE_FACTOR` radii, fall below the lowest socket − 0.75 m, stall, timeout).
- `state()` / `states()` are the renderer's ONLY read (positions converted to world metres); `carPose(alpha)` lerps the last two. `hash()` folds the run seed in (`seededHash`), so hash = f(level, build, seed); NaN poisons via `quant`'s distinct words in `src/physics`.
- `src/world/level.ts` — `Level` = `{ id, name, seed, startSocket, budget, par, maxTime, placeholderBuild(), parBuild?() }`, plain data; the `placeholderBuild()` seam now carries the REAL feel track (signature unchanged). The optional `parBuild` is the Level Designer's reference build for pars (brief §9.2); `scripts/gen-pars.mjs` falls back to `placeholderBuild` until a level ships one, so the feel track's real-kit chain is its own reference for now.
- `src/world/stars.ts` — the scoring layer of brief §1/§9.2, pure over a plain `RunResult` `{ status, time, piecesUsed, hazardsTouched }`: `starsFor` awards one star per independent line (finish; `piecesUsed <= par.pieces`; `time <= par.time` — recorded reading of "under par" in the Decision Log), `starGlyphs` is the one ★/☆ readout the result panel and the share card share, and `parFor(levelId, fallback)` answers from `pars.json` (`PARS`) when the generator has recorded a line, else the level's own `par`. The `RunOutcome` union already includes `hazard` for the stage-3 hazards `World` does not yet report.
- `src/world/pars.json` — GENERATED by `scripts/gen-pars.mjs` (`npm run pars`; CI gate `npm run pars -- --check` fails on drift — the brief's stage-4 "pars regenerated by script"). One entry per registered level `{ levelId, parPieces, parTime }`: the reference build replayed headless through `src/replay` (a build that does not finish is an error, not a par), `parTime` the measured finish ceil'd to 0.05 s so sub-tick jitter cannot move the 3-star line. Currently: the feel track (9 pieces, 3.05 s) plus all six kitchen rungs — the generator imports every level file since the L01 promise fix (session `2026-10-05 Stage 3 - L01 promise fix`), which is when the kitchen cells were re-measured for the re-authored `KITCHEN_GAP`. Note `parPieces` counts the whole reference build (fixtures included); the tray budget is the binding piece line in-game.

Standard rule: counter surface 5 mm under the finish deck, centred 0.45 m off the timed rail's axis (pure translation, yaw 0); kitchen04 additionally yaws −45° so the tap's `drip` anchor maps exactly onto the ground build's decked-sink seam — the authored wet patch's centre (the tap↔zone fix: neither the zone data nor the tap geometry moved; the PROP is PLACED — Decision Log 2026-10-07). `placeSet` composes `SET_ORIGIN` (the dev scene's canonical framing) with the mount; boot and kitchen03's fixture seating consume it, and `tests/unit/set-wiring.test.ts` re-derives every literal from live data — so any level geometry move drags the table with it (the stage-3 ladder-coherence pass re-derived `kitchen02`'s centre x, 1.0162 → 1.0112, when its two straights became one 0.18 m geometry and the cup came 5 cm nearer the start; the other rows are untouched).
- `src/world/levels/feeltrack.level.ts` — the one stage-2 level and the registry (`LEVELS`, `getLevel`). The build is the kit feel track expressed as data: `chain(FEEL_TRACK_KINDS, { params: FEEL_PARAMS, levelId, seed })` — 9 pieces (`ramp → straight → loop → gapLip → drop → landing → finishCup → bank → curve`; the `drop` is the gap's catch ramp, added with the 2026-10-06 feel-track landing fix — see [[feel]] Layout), laid by pure socket math (`fitSocket` under `chain`). Kinds AND parameters are IMPORTED from `src/feel/feeltrack.ts` (`FEEL_PARAMS` is exported now), not copied — when the Feel Engineer retunes a constant the level follows for free; `tests/unit/feeltrack-level.test.ts` (sample- and collider-fingerprint equality against `feelTrackRig().build`) is the seam that keeps the two routes honest. `startSocket` is derived from the harness rig's own release pose (`marks.start`, 0.9 of the ramp's pitch blend — the first piece's in-socket is a LEVEL patch of deck where the tuned rolling resistance outranks gravity and the car `stalls` in the grass), so spawn is data too and the game and the metrics release the same car. Measured (feel energy-audit retune, 2026-10-06: 0.52 m drop, `drop` catch piece, audited solver): finishes headlessly in 361 steps (3.01 s), identical from Node and the built page — retunes change the number; `Modules/replay.md` carries the current pinned hash (`099403c7`). The world route runs ~0.2 s faster phase through the ring than the feel harness's slab colliders; the drop constant is chosen where BOTH lines complete (see [[feel]]).

## Invariants

- A World is constructed from `(level, build, opts)` and nothing else (Track Kit invariant 4). No hidden world state reaches physics; the seed rides in through `build.seed`.
- The renderer never reads physics per frame; the frame loop in `src/boot.ts` only decides how many fixed steps the elapsed time pays for.
- Termination is a function of the data: terminal `status` or a fixed step cap — so replays of equal data execute equal step sequences.

## Known quirk (measured)

Rapier's query pipeline does not see freshly created colliders until the first `world.step()` propagates the broad-phase — the car's first support ray deterministically misses and the car sinks ~0.3 mm at step 0. Same ordering as the `src/feel` rigs, deterministic on every machine; left as-is on purpose.
