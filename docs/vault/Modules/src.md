> [!abstract] Role
> The browser entry point and shell of Gravity Works. Stage 2 replaced the placeholder with the real game shell: a fixed-timestep loop around the `World`, the builder tray, and a share-replay verification page.

## How it works

No router, no framework (per the brief's "small entity model, not a framework"). The fixed step lives in physics (`World.step`); the frame loop only decides *how many* fixed steps the elapsed time pays for (capped, so a background tab cannot fast-forward a run). Pure bits of the shell (`runStatusLine`, `nextLevelId`) are unit-guarded by `tests/unit/boot.test.ts` (the status line carries no hash since the shell-truth pass — the fingerprint lives in the `#gw-hash-details` disclosure); the DOM/canvas half by `tests/e2e/smoke.spec.ts`, `tests/e2e/builder.spec.ts` (whose expected piece counts import the level data — `FEEL_TRACK_KINDS.length`, `FEELTRACK.budget` — instead of mirroring it), `tests/e2e/result.spec.ts` (finish → panel; help drawer opens and renders), `tests/e2e/campaign.spec.ts` (the stage-4 room picker: boundary Next, locked-rung-says-why, unlocked-by-earned-star, real-UI bedroom01 finish, error-free set switch), `tests/e2e/loop.spec.ts` (the playtest-fix gate on the BUILT app), `tests/e2e/shell-truth.spec.ts` (the playtest E/F/G gate: keyboard-only L01 build, star-gated Next, non-black first paint, visible rotate) and the share-verified e2e.
