# Modules/share

> [!abstract] Role
> Share links with no server: `(levelId, build, seed, hash)` → canonical JSON → raw DEFLATE → base64url → a `#s=` URL fragment, the final state hash embedded so any viewer can recompute and print verified/mismatch (brief §8, §9.4). Owner: Systems Engineer.

## What it does

`src/share/share.ts` — `shareJson` emits the wrapper with keys ascending (`build`, `goal?`, `hash`, `lineage?`, `levelId`, `name?`, `par?`, `seed`, `v`) and the build embedded through `serialize`, so equal payloads are byte-equal before compression. `encodeShareUrl` compresses and base64urls it; `parseShareUrl` (alias `decodeShareUrl`) refuses garbage at both layers: `extractShareRef` rejects anything that isn't an `s=` fragment (an ordinary `#anchor` is never a share), and `fromShareJson` validates version, hash shape, seed integer and the build via `deserialize`.

Compression is injectable (`ShareCodec`): the browser uses platform `CompressionStream('deflate-raw')` (`platformCodec`); Node paths may pass a `zlib.deflateRawSync` codec. The module imports no Node APIs, so the browser bundle stays clean, and the two codecs are RFC1951-identical — `tests/unit/share.test.ts` proves interop in BOTH directions against `node:zlib`.

## Share card (stage 3, brief §8 "share card" + §9.4)

`src/share/card.ts` — `generateShareCard(state): Promise<Blob>` renders the final build state (live `scene` if given, else `buildTrackMeshes(build)` from `src/world`) into an offscreen WebGL canvas from `heroCameraFor` — the hero rig's front-up-right three-quarter attitude and fov, scaled to the build's own bounding box, because the fixed hero rig in `src/dev/cameras.ts` frames the provisional kitchen bowl and a card must frame the build actually being shared (Decision Log) — then composites a warm-paper caption strip in a 2D canvas: `cardCaption` (level, time, the shared `starGlyphs` readout, the verified mark when the share page answered) and the URL. Returns a PNG `Blob`; in Node it rejects with a clear "needs a browser canvas" rather than shipping a blank PNG. `downloadBlob` is the file-save sugar `src/boot.ts` uses for the `#gw-share-card` button on the shared-run page (`#gw-card-status` narrates: rendering card… / card ready / card failed).

## THE CHAIN — payload v2 (freeplay Lane C, 2026-10-12)

`SharePayload` grows four fields for the CHALLENGE half of a line (the re-probe's finding: the payload carried build+par yet LOSED the name, the cup-goal and the author's measured par, so a friend's ghost race printed `you vs par` for the WRONG game). **v2**: `name` (the line's, ≤ 48 chars — a name is a string, not an identity), `par` (the author's MEASURED run through the gen-pars ceil — `parOfRun` is one home for `scripts/gen-pars.mjs`'s `parTimeOf` law), `goal` (the placed cup's transform, 16 raw Matrix4 elements copied the guard's way — `cupGoalFromBuild` takes the LAST `finishCup` past the fixture quota, the same occurrence rule `World` reifies; PRESENTATION geometry only, the verdict's cup is read from BUILD, never from this field), `lineage` (the link whose ghost this run beat, identity by hash). **optional-on-read / mandatory-on-write-new**: `fromShareJson` accepts `v: 1` and `v: 2`; a v1 envelope that CARRIES a v2 field is garbage (absence is fine, garbage is not), and the game's writers (`src/boot.ts`'s share button, and since loop four the downhill's own `#gw-house-share` in `src/pages/house.ts` — the trailer verb: a payload carrying NOTHING the run did not already carry, since the input law means the receipt already commits the wind) stamp `v: 2` always. A payload with no v2 fields still writes the EXACT v1 bytes — which is what makes the fixtures real. **v1 links verify FOREVER** (the program's one true point of no return): `tests/fixtures/share-v1.json` holds four REAL v1 payloads — shipped par builds replayed through the shipped sim, encoded by the v1 writer; the file carries only the readable canonical envelopes (the `#s=` wire token is DERIVED in-test by raw DEFLATE + base64url of those bytes — no high-entropy literals for secret scanners to false-positive on) — and `tests/unit/share-v1.test.ts` proves both directions per fixture: the stored bytes parse, re-serialize byte-identically, decode from the wire token with either codec, and REPLAY to the embedded hash; the same build re-minted v2 replays to the SAME hash (the version hop moves no physics).

`src/share/chain.ts` — THE CHAIN store: the links this device PUBLISHED (every share press, `rememberLink`) or RACED (every accepted friend link) ride as payloads in `settings.records.chain` (no schema bump; validated on read, deduped by hash, FIFO-capped at `CHAIN_CAP` = 64), `chainLinkPayload` turns a row back into a race, `chainRankLine` phrases the rank as the count of links WALKED ON THIS DEVICE (the single-machine law; THE TALLY'S BADGES ARE NOT RANK INPUTS — the module never reads `records.badges`), and `beatLineage` grants a beat only to a finished run strictly ahead of a payload ghost's own re-simulated finish — since the final sheet probe (Decision Log 2026-10-12, Ghost-law extension) the shell passes the ACCEPTANCE as the mode: a run that accepted a hashed link ENDS in friend mode (`racedLink` with a hash in `src/boot.ts`), so an edit that lifts the link's car off the grid never un-races the link and the CHAIN's middle link mints (`tests/e2e/lineage.spec.ts`). The `#s=` VIEWER PAGE shows the challenge too (item (b)): `#gw-replay-payload-line` in `src/pages/share.ts` prints NAME · GOAL · PAR straight off the v2 fields — the name verbatim, the goal as the cup transform's TRANSLATION (the same read `cupGoalFromBuild` ships), the par in seconds — one calm line, only fields the payload actually carries; a v1 link prints nothing new (the absent-field law, fixture-token-tested). See [[Concepts/Chain]].

## Invariants

- The hash inside a payload is the ONLY trust anchor: replay recomputes, compare prints the verdict. Same-machine verification is exact, and since 2026-10-09 the cross-machine identity is MEASURED, not assumed: all 37 reference-build hashes match between linux-x64 and darwin-arm64 in CI (`tools/hash-atlas.mjs`, `Reference/Cross-platform determinism 2026-10-09`) — platforms outside those two remain unproven, and the verdict line stays machine-local — since program T2.2 the page's ONE honest line under the player reads `✓ verified · matches the link — re-simulated on this machine` ("on this machine" is the strongest claim a page can prove about itself; the retired `#gw-replay-badge` pill's wording law lives on in the line, and the fold beneath the player names what machines mean).
- A share URL is fully self-describing: `getLevel` + the embedded build determine the whole run (Track Kit invariant 4).
